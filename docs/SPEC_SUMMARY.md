# Выжимка ТЗ: Проект SpecGuard

> **Назначение системы:** Локальный CLI-агент, помогающий человеку оценить PR или коммит в GitHub на соответствие требованиям загруженных ТЗ с использованием RAG и GitHub MCP.

---

## 1. Ключевые требования (Scope)

### Входные данные и CLI
- **Форматы ТЗ:** TXT, Markdown, DOCX, текстовый PDF (без сканов/OCR). Неполное извлечение отображается явно.
- **Вход анализа:** Выбранное ТЗ + PR/коммит + краткое пояснение от пользователя.
- **Настройка моделей:** CLI поддерживает независимые конфигурации для текстовой LLM и Embedding-модели (обе через OpenAI-совместимый API, локально или в облаке).
- **Выбор языка отчёта:** Настраивается в CLI (отчёт на выбранном языке, цитаты могут оставаться на языке источника).

### Анализ и логика агента
- **Двунаправленный анализ:**
  1. Выявление нарушений требований ТЗ (Violations).
  2. Фиксация реализованных требований (Implementation tracking).
- **Разделение степеней уверенности:** Подтверждённое нарушение vs подозрение/неопределённость. Каждое утверждение сопровождается ссылкой на ревизию, файл, строку и цитату из ТЗ.
- **Безопасность (Prompt Injection):** ТЗ и код анализируются строго как данные, команды из них не влияют на системные инструкции агента.
- **Ограничения источников:** При неполных данных, усечении или недоступности файлов агент формирует частичный отчёт с явным списком ограничений.
- **Merge-коммиты:** Сравниваются строго с **первым родителем** (first parent SHA указывается в отчёте).

### История и оспаривание
- **История проверок:** Сохранение всех запусков, протоколов и исходных материалов.
- **Обновление ТЗ:** При перезаписи старого ТЗ сохраняются результаты прошлых проверок.
- **Оспаривание (Re-eval):** Пользователь может оспорить замечание комментарием; агент пересматривает вывод строго на сохранённых исходных материалах.

### GitHub & MCP
- Read-only доступ к репозиторию через GitHub MCP (pull_request_read, get_commit, get_file_contents).
- Агент **не** запускает код и **не** пишет в GitHub.

## 2. План оценки и тестовый репозиторий (AC-013...AC-016)
Необходимо подготовить отдельный тестовый репозиторий и локальный изолированный набор эталонов (Ground Truth) минимум на 10 сценариев:
1. Точная реализация требования.
2. Прямое нарушение требования.
3. Отсутствие нарушения (код корректен).
4. Межфайловое нарушение.
5. Синонимы и разные термины в ТЗ и коде.
6. Исключение описано в другом разделе ТЗ.
7. Merge-коммит (сравнение с 1-м родителем).
8. Усечение данных / частичный diff / недоступный файл.
9. Prompt injection в коде или комментарии PR.
10. Оспаривание вывода пользователем.
