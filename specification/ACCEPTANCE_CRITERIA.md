# Критерии приёмки — утверждено

Критерии утверждены в приведённой редакции; численные пороги AI-качества и состав эталонного набора остаются открытыми и требуют отдельного определения.

- AC-001 [FR-001, FR-002]: в проверочных примерах загружаются TXT, Markdown, DOCX и текстовый PDF; неполное извлечение явно отображается.
- AC-002 [FR-003, FR-004]: пользователь выбирает ТЗ, кратко поясняет выполненное и запускает анализ PR и обычного коммита; агент автоматически формирует отчёт о требованиях ТЗ, коде и возможных нарушениях.
- AC-003 [FR-005, FR-006]: сценарии используют GitHub MCP для чтения и RAG для поиска требований; записи в GitHub и запуск кода не выполняются.
- AC-004 [FR-007, NFR-003]: в CLI независимо настраиваются OpenAI-совместимые API текстовой LLM и embedding-модели; изменение LLM не подменяет embedding-модель. Несовместимость контракта отображается, качество непроверенной конфигурации не заявляется проверенным.
- AC-005 [FR-008, FR-013]: отчёт на выбранном пользователем в CLI языке содержит обнаруженные замечания, источники и ограничения; неподтверждённое замечание отличается от подтверждённого; цитаты могут сохранять язык источника.
- AC-006 [FR-009]: большое изменение не отклоняется исключительно из-за размера; недоступные файлы и неполная выдача MCP указаны в частичном отчёте.
- AC-007 [FR-010, FR-011]: после замены актуального ТЗ материалы предыдущей проверки доступны; повтор обновлённого PR сохраняется в истории наряду с прошлой проверкой.
- AC-008 [FR-012]: пользователь передаёт комментарий к оспариваемому выводу и получает повторное рассмотрение. Пересмотр использует сохранённые материалы исходной проверки, даже если актуальные данные изменились.
- AC-009 [NFR-001, NFR-002]: в проверочных случаях недоверенные инструкции не расширяют права; пропуски и известные ревизии отражены в отчёте.
- AC-010 [FR-004, FR-006]: измеряются retrieval, корректность выводов, доказательств и охвата по EVALUATION_PLAN.md. Численные пороги и эталонные данные требуют отдельного утверждения; одного измерения недостаточно для приёмки качества.

- AC-011 [FR-001]: пользователь явно выбирает заменяемый документ; конфликты ТЗ показываются человеку с источниками.
- AC-012 [NFR-005]: CLI запускается локально на MacBook Pro M5/16 ГБ; embedding API может быть локальным или внешним. Для выбранного подключения проверяется генерация векторов и совместимость с индексом.

- AC-013 [TEST-001–TEST-005]: подготовлены тестовый GitHub-репозиторий и изолированный локальный набор эталонов; обязательные сценарии связаны с конкретными PR/коммитами, ревизиями и ТЗ, а ожидаемые ответы недоступны анализатору.
- AC-014 [TEST-002, TEST-007]: через живой GitHub MCP выполнены проверки PR, обычного и merge-коммитов; протокол содержит ревизии и SHA первого родителя merge. Несовпадение фикстуры отдельно отнесено к ошибке входа.
- AC-015 [TEST-006, TEST-010]: проверены контролируемые сбои адаптера; результаты имитации отделены от живой интеграции. При недоступной базе отчёт указывает ограничение и не приписывает проблему выбранному изменению.
- AC-016 [TEST-008, TEST-009]: для прогонов сохранены входы, профили, доказательства и отдельные показатели качества; причины технических и оценочных ошибок различаются. Численные пороги утверждаются отдельно.
