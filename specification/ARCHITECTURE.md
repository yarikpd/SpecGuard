# Архитектура — утверждено

Утверждено как часть ТЗ. Конкретные варианты, явно отмеченные рекомендациями или открытыми вопросами, предстоит выбрать или проверить отдельно.

В локальном CLI пользователь выбирает загруженное ТЗ и PR или коммит, кратко поясняет выполненное, выбирает язык отчёта и настройки двух моделей, затем запускает проверку. Подготовка документа сохраняет источник и создаёт индекс RAG. Адаптер GitHub через MCP собирает изменения и необходимый контекст с происхождением и ограничениями. Оркестратор строит карту изменений, извлекает кандидатов требований и анализирует два вопроса: возможные нарушения и реализацию требований выбранного ТЗ. Результаты проверяются и отображаются человеку вместе с доказательствами и пробелами.

Контракты: вход проверки (выбранное ТЗ, краткое пояснение, объект GitHub, профили текстовой и embedding-модели), требование с источником, результаты retrieval, доказательство с ревизией, оценка с неопределённостью, прогресс и пропуски. Техническая готовность индекса не подтверждает правильность извлечения требований. Модельный ответ проверяется по схеме; исправление формата не исправляет факты. Происхождение, точность цитаты и смысловая поддержка вывода проверяются отдельно.

Обработка больших данных выполняется частями с сохранением прогресса; завершение очереди не гарантирует обнаружения всех требований. Межфайловый проход проверяет конкретные гипотезы по исходным фрагментам, а не только по суммаризациям. Без исходной ревизии наблюдение в конечном коде не доказывает, что изменение внесено выбранным PR. При неполных данных область заключения ограничивается доступными материалами.

Текстовая LLM и embedding-модель используют независимо настраиваемые OpenAI-совместимые API; каждый сервер может быть локальным или внешним. Совместимость интерфейса не гарантирует качество. Доступ к MCP и retrieval организует приложение; обязательная поддержка вызова инструментов моделью не предполагается. Развёртывание локально на MacBook Pro M5 с 16 ГБ памяти. Пересмотр использует исходные материалы, новые данные проверяются отдельным запуском; сроки и бюджет не установлены.

Проверка merge-коммита использует первого родителя, SHA которого отображается. При недоступной базе анализ доступного head ограничен наблюдением текущего состояния. Для оценки качества в ходе реализации подготавливается отдельный учебный репозиторий; эталоны хранятся вне доступа анализатора.
